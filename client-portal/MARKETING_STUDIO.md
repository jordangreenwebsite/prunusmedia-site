# Marketing Studio — read-only Content360 pilot
The owner successfully tested Bearer-authenticated GET accounts/posts/media and created an unpublished draft manually. This module does not create drafts, upload, schedule, publish or run automatically.
 
Configure the separate prunus-website-clients Worker only:
- CONTENT360_API_TOKEN: encrypted runtime secret, already reported configured by owner; never put value in source or logs.
- CONTENT360_WORKSPACE_ID: runtime text variable, exact workspace UUID from the Content360 dashboard URL.
- CONTENT360_OWNER_EMAIL: encrypted runtime secret containing the exact owner login email, also in existing ADMIN_EMAILS. Other admins and client users are denied.

Use existing portal sign-in and open /marketing-studio (or agency dashboard link). Missing owner configuration fails closed. Each endpoint requests a single provider page only and displays bounded metadata, not total counts, raw posts, media URLs, personal IDs or secrets. HTTP failures are displayed without logging raw bodies. No provider-supplied pagination links are followed; redirects rejected. No new DB migration or dependencies. No changes to Certificates, blog publishing, or Stripe.

Release gate: run full portal test suite and validate actual Cloudflare secret retention before deploy; owner signs in, confirms three sections load and no credential appears in HTML or network responses; signed-out, client and other admin sessions must be denied. No unauthorised account writes. Future draft and schedule operations require separate account allowlists, audit/idempotency, explicit approval and real acceptance tests.
## Draft-only second phase
Set `CONTENT360_DRAFT_ACCOUNT_ID` in the same Worker dashboard to the verified owner Prunus Media Facebook page's Content360 numeric ID (not a Facebook platform ID). Until configured the draft form fails closed. Revalidates ID, exact permitted page name, Facebook page provider and authorised status against the accounts endpoint before every attempt. Requires owner login, same-origin POST and explicit approval. Sends only the previously tested draft payload, no media or schedule fields; saves a SHA-256 content/account/workspace digest and attempt state in migration 0011_marketing_studio_drafts.sql. Identical content cannot be resent automatically even on errors, pending/uncertain attempts require manual provider reconciliation; no reset route. A successful HTTP status alone is insufficient: expects provider draft status, numeric ID, no scheduled/published timestamp; otherwise check Content360 directly. This does not prove the provider honours the payload in every case. Release only after full tests, migration and actual owner-approved draft acceptance. Do not use client/personal accounts or publish/schedule yet. No token or raw post content stored in ledger.

## Existing-image selector
The owner verified that the provider accepts an existing media ID as a string in `versions[].content[].media[]`, not a media object. The draft form optionally selects one image from the first 100 rows of the existing media endpoint (first page only). Images are revalidated server-side immediately before submission; video, unknown IDs and arbitrary URLs are rejected. Only workspace-specific Content360 CDN thumbnails are displayed, without forwarding the API token. Text-only drafts remain available on library failure. Duplicate protection includes the chosen image ID while preserving existing text-only digests. Both direct and data-wrapped draft responses are recognised. No upload, scheduling, publishing or expanded account permission. The owner must verify the selected image in the resulting draft in Content360 before accepting this phase.
